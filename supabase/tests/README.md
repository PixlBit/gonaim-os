# Schema constraint tests

الغرض ليس اختبار Postgres، بل إثبات أن **القواعد الحاكمة في الوثيقة صارت قيودًا في القاعدة**
ولا يمكن تجاوزها من كود التطبيق أو من نداء نموذج.

## ما يثبته الاختبار

| # | القاعدة | المصدر |
| --- | --- | --- |
| 1–2 | الملاحظة المباشرة ليست احتمالًا، والاستنتاج لا يكون بلا ثقة | §5.2، Event Taxonomy §2 |
| 4 | نفس الحدث لا يُسجَّل مرتين | Event Taxonomy §2 |
| 5–6 | `sensitive` و`vaulted` لا يغادران الجهاز ولا كمتجه | ADR-0005 |
| 8 | بلا مصدر لا توجد ذاكرة | ADR-0004 |
| 9–10 | السقف الصلب: فعل خارجي أو مدمر لا يتجاوز L3 أبدًا | ADR-0007 |
| 12 | لا علاقة بين عقدة ونفسها | §6 |
| 13 | معادلة XP تُحسب في القاعدة، لا في الواجهة | §19.3 |

## التشغيل محليًا

```bash
createdb gonaim_test
psql -v ON_ERROR_STOP=1 -d gonaim_test -f supabase/migrations/0001_init.sql
psql -d gonaim_test -f supabase/tests/0001_constraints_test.sql
```

المتوقع: **٩ رفض و٤ قبول**. أي قبول لحالة يفترض رفضها = ثغرة في نموذج الأمان، لا خطأ اختبار.

> ملاحظة: الاختبار يحتاج `pgvector` و`auth.uid()`. على قاعدة محلية بلا Supabase،
> استبدل `vector(1024)` بـ`text` وعرّف `auth.uid()` كدالة ثابتة — راجع سجل الجلسة.
